- 요청: "재접속 시 달맵이나 운하맵처럼 다른 곳에서 접속을 종료했어도 호숫가에서 접속되는 문제 해결"

- 서버(Worker) 변경: **없음**

## 원인
- 달(실시간 방 7)·운하(방 20)에 있다는 정보가 **이 탭의 sessionStorage**(`nk_sky`·`nk_sea`)에만 있었어요.
- sessionStorage는 탭·브라우저를 닫으면 지워져요. 그래서 창을 닫고 다시 열면 늘 호숫가(방 1~4)로 시작했어요. (새로고침은 같은 탭이라 맵이 유지됐어요.)

## 수정 (`game-v2.js`, `boot-v85.js`)
- **저장:** 마지막 맵을 기기 저장소 `localStorage.nk_lastMap = {m:'moon'|'canal'|'lake', t, from}` 에 남겨요. `from` 은 맵에 가기 전 호숫가 번호(1~4).
  - 맵 이동할 때(`skySwitch`·`seaSwitch`)와 접속이 끝났을 때(실제 접속한 방 기준) 갱신.
  - 숨김 시험방(9)·미리보기(`NK_PREV`)·관전은 저장하지 않아요.
  - `boot-v85.js` 의 계정 칸별 저장 목록(`PER`)에 `nk_lastMap` 추가 → 계정 칸마다 따로.
- **복원 (`MAPRES`):** 새 탭에서 처음 열 때만(`nk_mapTab` 표시가 없을 때) `nk_lastMap` 을 읽어 `nk_sky`/`nk_sea`·`nk_skyFrom`/`nk_seaFrom` 을 다시 넣어요 → 기존 달·운하 시작 경로(`SKYBOOT`·`SEABOOT`)를 그대로 써요. 같은 탭에서 이미 정한 맵은 건드리지 않아요.
- **입장 조건 확인 (`mapBlock` → `mapFallback`):** 접속 직전에 확인하고, 안 맞으면 "… · 원래 호숫가로 가요" 알림 뒤 호숫가(`from`)로 다시 열어요.
  - 달: Lv.50 미만 / 달 맵이 닫혀 있음(`skyOn()`)
  - 운하: 운하가 닫혀 있음(`seaTownOn()`, 서버 `play.seaTown`)
  - 방이 가득(7·20 `full`)
  - `skyOn`·`seaTownOn` 은 블록 안 `const` 라 `window.__nkMapOpen` 훅으로 불러요.
- **시작 화면:** 맵에서 이어질 때 서버 고르기 화면 제목이 "어디로 갈까요?"가 되고, 맨 위에 🌙 달 / ⛵ 윤슬 운하 「마지막에 있던 곳 · 여기서 이어서」 칸이 선택돼 있어요. 아래 "또는 호숫가로" 1~4를 누르면 그 호숫가로 가요(`mapLeave`).
  - 직접 고른 호숫가를 「사람 있는 서버 자동 고르기」(`svAuto`)가 덮어쓰던 것 → `nk_svMan` 표시로 막음.

## 남은 점
- 실제 유저 방(달 7·운하 20)에 실제 계정으로 접속해서 확인하지는 않았어요(테스트는 9번 방). 같은 경로라 동작은 같아야 하지만 **미완료**.
- 폴백 뒤 호숫가 번호는 「사람 있는 서버 자동 고르기」 설정이 켜져 있으면 사람 있는 호숫가로 바뀔 수 있어요(기존 설정 동작).
- 다른 기기에서 접속하면 그 기기에 남은 마지막 맵을 따라요(맵 정보는 서버가 아니라 기기에 저장).
