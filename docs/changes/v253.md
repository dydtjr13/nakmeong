## 무엇이 바뀌었나 (일반 유저 기준)
- **하우징 섬도 멀티예요.** 섬에 들어가면 같은 서버에서 온 사람들과 함께 섬 방(🏡 하우징 섬)에 들어가요. 서로 캐릭터가 보이고, 움직임·채팅·이모트가 오가요.
- 섬 채팅은 출발한 호숫가 채팅과 이어져요. 호숫가에서는 섬 채팅 앞에 「🏡 하우징 섬」이 붙어요. (운하·달과 같은 방식)
- 위쪽 접속자 알약에 섬 인원(🏠)이 함께 보이고, 서버 목록 인원에도 섬에 있는 사람이 포함돼요.
- **다른 사람 텃밭도 보여요.** 내 텃밭은 언제나 내가 고른 집터에 보여요. 다른 사람이 고른 집터가 내 집터와 다르면 그 사람 텃밭(울타리·작물·자라는 단계)이 그 자리에 보이고, 가까이 가면 「🌱 ○○님 텃밭」 이름이 떠요. 같은 집터를 고른 사람이 여럿이면 먼저 들어온 한 명만 보여요. 내 집터와 겹치면 숨겨요.
- **텃밭을 누르면 크게 보여요.** 이제 텃밭 앞에 멈춰도 카메라가 저절로 움직이지 않아요. 텃밭을 한 번 누르면(클릭/탭) 크게 보기, 크게 본 상태에서 칸을 누르면 심기·수확, 텃밭 바깥을 누르거나 걸어가면 원래대로 돌아와요.
- 평소에는 칸마다 붙던 이름표 대신 텃밭 위에 요약 한 줄(「🌱 내 텃밭 · 수확 N · 빈 칸 N / 🔍 눌러서 크게 보기」)만 보여요. 칸 이름표는 크게 볼 때만 보여요.
- 25칸처럼 칸 간격이 좁을 때는 이름표를 작게 줄여요(다 자람 ✓, 자라는 중은 진행 막대만). 이름표끼리 겹치지 않아요.
- 휴대폰 화면이 갑자기 멈추거나(그래픽 손실) 하면 저장 후 저절로 다시 그리고, 다시 그려지지 않으면 섬으로 자동으로 다시 들어와요.

## 왜
- ① 섬은 v252에서 실시간 방 접속을 일부러 건너뛰었어요(`!HOUSEBOOT`일 때만 접속). 그래서 섬에 가면 혼자였어요.
- ③ 「텃밭 앞에서 화면 전환」은 v252의 자동 텃밭 카메라가 멈춤/움직임마다 들어갔다 나갔다 한 것과 같은 동작이에요. 25칸이면 칸마다 작물·그림자·고리·이름표를 따로 그려서(25칸 크게 보기 141 그리기 호출) 휴대폰 GPU 부담이 컸어요.

## 튕김: 무엇을 근거로 고쳤나 (정직하게)
- **실기기에서 튕기는 원인 자체는 재현하지 못했어요.** 헤드리스 크롬(390×844, 25칸)에서 카메라 들어가기/나가기, 화면 회전, 백그라운드 전환, 심기+수확을 수십~100회 반복해도 강제 GC 후 JS 힙·지오메트리·텍스처·셰이더·DOM 수가 늘지 않았어요(누수 없음).
- 그래서 휴대폰에서 튕김으로 보이는 가장 흔한 경우(① GPU 메모리 부족으로 WebGL 컨텍스트 손실 ② 탭 메모리 압박)를 **강제로 일으켜서** 복구 경로를 만들고 확인했어요.
- 고친 것:
  1. 자동 텃밭 카메라 들락날락 제거 → 눌러서 크게 보기 (사용자가 말한 「화면 전환」 반복 자체를 없앰)
  2. WebGL 컨텍스트 손실 처리: `webglcontextlost`에서 기본 동작 막고 즉시 저장, 3.5초 안에 복구되면 계속, 안 되면 섬으로 자동 재입장(2분에 최대 2번)
  3. 25칸 그리기 비용 줄이기: 작물(작물·단계별)·그림자·고리를 인스턴싱 → 25칸 크게 보기 그리기 호출 **141 → 77** (텃밭 몫 약 81 → 19)
  4. 칸마다 만들던 그림자·고리 지오메트리/재질을 공유
  5. 수확 칩 반짝임을 box-shadow 다시 그리기 대신 opacity 애니메이션으로 (GPU 합성만)
- 텍스처: 텃밭 텍스처 14장 약 1.16Mpx로 이미 작아서 줄이지 않았어요. 장면 전체 약 102장 15.7Mpx 대부분은 기존 게임 맵(512²)이에요.

- **로컬 멀티 (4클라이언트: 섬 3 + 호숫가 1)**: 섬 3명 모두 방 21, 서로 보임(캐릭터 높이 0.1, 위치 정상), 섬 채팅이 호숫가에 「🏡 하우징 섬」 라벨로 도착, `/servers` 서버1 n=4(isl=3), 접속자 알약 총 4명. 다른 사람 텃밭: A(17번) → B(18번) 보임 · 같은 17번 C는 숨김, B → A만 보임(집터당 1명), C(17번) → B 보임. 오류 0건.
- 이모트·움직임 따로 확인 (섬 2명): A가 채팅창 이모트 버튼(😊)을 누르면 B가 받음, A가 움직이면 B 화면의 A 위치가 바뀜 (-732.1,-43.5 → -730,-45). 오류 0건.
- **튕김 대비 (390×844, 25칸, 크게 보기)**: 탭으로 크게 보기 켜고/끄기 100회 → JS 힙 60.1 → 61.7MB, 지오메트리 202 · 텍스처 64 · 셰이더 44 그대로, 그리기 호출 77~79, DOM 약 592~599, FPS 9~10 (헤드리스 소프트웨어 렌더라 실제 기기보다 낮음). 메모리 압박(critical) 이상 없음. 컨텍스트 손실/복구 20번 → 20번 모두 복구, 계속 그려짐. 복구 안 되는 손실 → 섬으로 자동 재입장, 25칸·방금 심은 칸 저장 유지. 오류 0건.
